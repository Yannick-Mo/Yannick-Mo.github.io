epoll 笔记整理

1. epoll 概述

epoll 是 Linux 内核提供的一种高性能 I/O 多路复用机制，用于同时监控大量文件描述符（FD）上的 I/O 事件（可读、可写、异常等）。它通过 事件驱动 的方式高效处理并发连接，特别适合高并发网络服务器（如 Nginx、Redis 等）。

2. epoll 实例的本质

2.1 内核数据结构

一个 epoll 实例在内核中主要由两部分组成：

  • 红黑树：存储所有被监控的 FD 及其关注的事件掩码（如 EPOLLIN、EPOLLOUT）。
  • 就绪链表：当某个 FD 上有事件就绪时，内核将其从红黑树移至该链表。

2.2 用户空间访问入口

用户通过 epoll_create / epoll_create1 创建的 epoll FD 是访问该内核实例的唯一接口。这个 FD 不对应任何磁盘文件，而是指向内核中的 epoll 对象。

3. 核心 API

3.1 创建 epoll 实例：epoll_create 与 epoll_create1

  • epoll_create(size)

    • 已被视为过时接口。
    • 参数 size 目前已被内核忽略，但历史原因需要传入一个大于 0 的值。
    • 返回的文件描述符默认不带有 O_CLOEXEC 标志（即 fork 后子进程会继承该 FD）。

  • epoll_create1(flags)

    • 是 epoll_create 的现代化版本。
    • 接受一个 flags 参数，目前只支持 EPOLL_CLOEXEC。
    • 可以原子地为返回的 epoll FD 设置 close-on-exec 标志，避免多线程或 fork() + exec() 场景下的竞态条件。
    • 当 flags == 0 时，行为与 epoll_create 完全一致。

推荐做法：现代 Linux 编程中应优先使用

1

int epfd = epoll_create1(EPOLL_CLOEXEC);

以避免描述符泄露和竞态风险，同时代码更简洁安全。 如果出于某些原因需要兼容旧行为，可使用 epoll_create1(0)，但其返回的 FD 不带 O_CLOEXEC，如需该标志只能在之后通过 fcntl(epfd, F_SETFD, FD_CLOEXEC) 手动设置。

错误处理：当 flags 为非 0 且非 EPOLL_CLOEXEC 时，epoll_create1 返回 -1，并置 errno = EINVAL。

3.2 管理监控事件：epoll_ctl 

1

int epoll_ctl(int epfd, int op, int fd, struct epoll_event *event);
  • 功能：向 epoll 实例添加、修改或删除被监控的 FD。
  • 参数：
    • epfd：由 epoll_create1 返回的 epoll FD。
    • op：
      • EPOLL_CTL_ADD：注册新的 FD。
      • EPOLL_CTL_MOD：修改已注册 FD 的事件掩码。
      • EPOLL_CTL_DEL：移除已注册的 FD。
    • fd：要监控的目标文件描述符（如 socket、管道等）。
    • event：指向 struct epoll_event 的指针，指定关注的事件和关联的用户数据。

3.3 等待事件：epoll_wait 

1

int epoll_wait(int epfd, struct epoll_event *events, int maxevents, int timeout);
  • 功能：等待已监控的 FD 上发生就绪事件，返回就绪事件列表。
  • 参数：
    • events：输出数组，存放已就绪的 epoll_event 结构体。
    • maxevents：数组容量。
    • timeout：超时毫秒数；-1 表示无限阻塞，0 表示立即返回（非阻塞）。
  • 返回值：就绪事件数量，出错返回 -1。

高效的关键：epoll_wait 仅从内核就绪链表中取出事件，时间复杂度 O(1)，与监控的 FD 总数无关。

epoll_event 用于描述一个 I/O 事件，是 epoll_ctl 和 epoll_wait 操作的核心数据结构。

struct epoll_event {
    uint32_t     events;      // 事件掩码
    epoll_data_t data;        // 用户数据
};

typedef union epoll_data {
    void    *ptr;
    int      fd;
    uint32_t u32;
    uint64_t u64;
} epoll_data_t;

4.1 events 常见标志

  • 基本事件
    • EPOLLIN：FD 可读（包括对端正常关闭）。
    • EPOLLOUT：FD 可写。
    • EPOLLRDHUP：对端关闭连接或半关闭写端（需内核版本支持）。
    • EPOLLPRI：有紧急数据可读（带外数据）。
  • 异常/挂断类（内核自动监听，无须显式注册）
    • EPOLLERR：发生错误。
    • EPOLLHUP：挂断（如管道写端关闭）。
  • 控制行为类
    • EPOLLET：启用边缘触发（Edge Triggered）模式，默认是水平触发。
    • EPOLLONESHOT：一次性监听，事件触发后自动取消监控，若要继续监控需再次 EPOLL_CTL_MOD。

4.2 data 联合体

可用于存储与事件关联的上下文信息，四种选择：

  • fd：直接存储所监控的文件描述符（最常用）。
  • ptr：指向用户自定义结构体，可携带更多上下文（如连接状态、缓冲区等）。
  • u32 / u64：存储整数 ID 或索引。

在 epoll_wait 返回时，可以从就绪的 events[i].data 中取回注册时保存的信息，快速定位是哪个 FD 或连接产生的就绪事件。

5. 工作流程与触发模式

5.1 整体工作流程

  1. 注册阶段 用户调用 epoll_ctl(EPOLL_CTL_ADD) 将目标 FD（如 TCP 监听 socket 或连接 socket）添加到 epoll 实例的红黑树中。内核同时为每个 FD 注册一个回调函数。
  2. 就绪通知 当 FD 上发生所关注的事件（如数据到达），内核通过回调将该 FD 加入就绪链表。
  3. 事件检索 用户调用 epoll_wait 直接从就绪链表读取就绪的 FD，避免遍历所有监控的 FD。
  4. 重新注册/修改 根据模式（特别是 EPOLLONESHOT 或 ET 模式的需要），应用程序可在处理后重新修改事件掩码。

5.2 水平触发（LT）与边缘触发（ET）

  • 水平触发（默认）
    • 只要 FD 仍处于就绪状态（例如接收缓冲区还有未读完的数据），每次 epoll_wait 都会持续通知该事件。
    • 编程简单，不易遗漏事件，但不处理会重复通知，可能引发"惊群"问题（单连接多唤醒）。
  • 边缘触发（EPOLLET）
    • 仅在 FD 状态从"未就绪"变为"就绪"的瞬间通知一次。例如接收缓冲区从空变为有数据时，只通知一次。
    • 要求应用程序一次性将数据读完（通常需要循环 read 直到返回 EAGAIN），否则剩余数据不会再触发新事件。
    • 必须配合非阻塞 I/O 使用，避免因某次 read/write 阻塞导致整个事件循环停顿。

选择建议：大多数场景使用默认的 LT 即可，逻辑简单；追求极致性能且能严格控制非阻塞逻辑时，可选用 ET 模式。

6. epoll FD 的深层理解：它到底是什么文件描述符？

  • 它是一个文件描述符，但不指向磁盘文件。
  • 在 /proc/<pid>/fd/ 下查看，会看到类似 3 -> anon_inode:[eventpoll] 的符号链接，表明它是一个匿名 inode，对应内核中的 epoll 对象。
  • 该 FD 可像普通 FD 一样被 close() 关闭，进程退出时内核会自动回收 epoll 实例。
  • 它的"操作"不是 read/write，而是通过 epoll_ctl、epoll_wait 等专用接口来完成。

对比普通文件 FD：

特性 epoll FD 普通文件 FD (如 open())
对应实体 内核 epoll 实例（事件管理器） 磁盘文件、设备等
文件系统可见性 仅 /proc 下可见（匿名 inode） 正常文件系统路径可见
主要操作 epoll_ctl / epoll_wait read / write / lseek 等

7. 与 select/poll 的对比

特性 select poll epoll
FD 数量限制 通常 1024 (FD_SETSIZE) 无硬性限制（受内存影响） 无硬性限制（受内存影响）
时间复杂度 O(n) （每次轮询所有 FD） O(n) O(1) （仅处理就绪链表）
内存拷贝 每次调用需将整个 FD 集合从用户态拷贝到内核态 同 select 只需一次注册，采用 mmap 减少拷贝
通知机制 遍历所有 FD 找就绪 遍历所有 FD 找就绪 回调驱动，内核仅返回就绪 FD
工作模式 仅支持 LT 语义 仅支持 LT 语义 支持 LT 和 ET 两种模式

结论：在需要管理数万并发连接的场景，epoll 的性能远超 select/poll，是 Linux 下高性能网络编程的标准方案。

#include <sys/epoll.h>
#include <netinet/in.h>
#include <arpa/inet.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

#define MAX_EVENTS 10
#define BUFFER_SIZE 1024

int main() {
    int listen_fd = socket(AF_INET, SOCK_STREAM, 0);
    if (listen_fd == -1) { perror("socket"); return 1; }

    struct sockaddr_in server_addr;
    memset(&server_addr, 0, sizeof(server_addr));
    server_addr.sin_family = AF_INET;
    server_addr.sin_addr.s_addr = INADDR_ANY;
    server_addr.sin_port = htons(8080);

    if (bind(listen_fd, (struct sockaddr*)&server_addr, sizeof(server_addr)) == -1) {
        perror("bind"); close(listen_fd); return 1;
    }
    if (listen(listen_fd, SOMAXCONN) == -1) {
        perror("listen"); close(listen_fd); return 1;
    }

    // 创建 epoll 实例（推荐 EPOLL_CLOEXEC）
    int epoll_fd = epoll_create1(EPOLL_CLOEXEC);
    if (epoll_fd == -1) {
        perror("epoll_create1");
        close(listen_fd);
        return 1;
    }

    // 注册监听 socket，关注读事件（新连接）
    struct epoll_event ev, events[MAX_EVENTS];
    ev.events = EPOLLIN;
    ev.data.fd = listen_fd;
    if (epoll_ctl(epoll_fd, EPOLL_CTL_ADD, listen_fd, &ev) == -1) {
        perror("epoll_ctl: listen_fd");
        close(epoll_fd); close(listen_fd);
        return 1;
    }

    // 事件循环
    while (1) {
        int nfds = epoll_wait(epoll_fd, events, MAX_EVENTS, -1);
        if (nfds == -1) { perror("epoll_wait"); continue; }

        for (int i = 0; i < nfds; i++) {
            if (events[i].data.fd == listen_fd) {
                // 新连接
                struct sockaddr_in client_addr;
                socklen_t len = sizeof(client_addr);
                int conn_fd = accept(listen_fd, (struct sockaddr*)&client_addr, &len);
                if (conn_fd == -1) { perror("accept"); continue; }

                // 将新连接加入 epoll（边缘触发示例，也可用默认 LT）
                ev.events = EPOLLIN | EPOLLET;
                ev.data.fd = conn_fd;
                if (epoll_ctl(epoll_fd, EPOLL_CTL_ADD, conn_fd, &ev) == -1) {
                    perror("epoll_ctl: conn_fd");
                    close(conn_fd);
                }
            } else {
                // 客户端数据
                char buffer[BUFFER_SIZE];
                int conn_fd = events[i].data.fd;
                int n = read(conn_fd, buffer, BUFFER_SIZE);
                if (n <= 0) {
                    close(conn_fd);
                    // epoll 会自动移除已关闭的 FD（具体取决于内核版本，亦可显式 epoll_ctl DEL）
                } else {
                    write(conn_fd, buffer, n); // 简单回显
                }
            }
        }
    }

    close(epoll_fd);
    close(listen_fd);
    return 0;
}

9. 核心优势总结

  1. 事件驱动：只关注就绪 FD，无遍历开销。
  2. 零拷贝：利用 mmap 减少用户态与内核态的数据复制。
  3. 无 FD 数量硬限制：仅受系统内存约束，可支撑海量并发连接。
  4. 支持 ET 与 LT：可灵活选择性能或编程便利性。
  5. API 设计安全：epoll_create1(EPOLL_CLOEXEC) 原子地设置 close-on-exec，避免竞态泄露。

epoll 的高效设计和简洁接口使其成为 Linux 高并发网络编程的首选方案。
